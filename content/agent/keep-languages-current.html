What your agent does

  1. Runs npx i18next-cli extract, so new keys reach every language file.
  2. Reads git diff on the English files and translates every key whose English value changed again, in every other language.
  3. Runs npx i18next-cli status and npx i18next-cli lint; both pass, and lint reports no missing placeholder.
  4. Lists the keys it changed, per language.

Two kinds of change

  • A new text gets a new key. i18next-cli extract writes it into every language file, and i18next-cli status reports it as missing until it is translated. In CI, before the build, that stops the deploy.
  • A changed text under the same key keeps its old translations, and when the English is edited in the translation file, no i18next-cli command reports it: status counts the key as translated. Step 2 of the prompt closes that gap from the git diff. When the meaning changes, a new key is the safer way: then status reports it in every language.

Two ways to keep the other languages current

The agent translates from the diff

Step 2 of the prompt reads git diff on the English files and translates every key whose English changed again, in every language. It costs nothing extra and fits when one person or the agent keeps the languages.

When the English text of a translated key changes in Locize (edited there, or synced from the repository with locize-sync --update-values), Locize marks that key's translation in every language as needing review (the setting "Review on source change", on by default). Translators and reviewers who do not code see per language what to re-check, in a web editor. It fits when several people translate, or when a missed change costs more than the setup.

Before it goes live

  • Have each changed translation read by someone who speaks the language. An agent's translation is a first draft.
  • Compare the agent's list with the diff: every English key that changed appears in every language.
  • Add npx i18next-cli status to CI, so a new text without its translation stops the build.
