Your site or app in more languages. Every text in a plain file in your repo.

i18next is the open-source way to make a site or app multilingual: the rules of each language, the same in React, Next, Astro and many other frameworks. Written by you or by your agent, readable by both.

One solution, the same everywhere

The same library, the same translation files and the same t('key') call in your app, your marketing site and your content site. What you or your agent learned once carries over.

  • ReactApps and SaaS, with react-i18next. Docs
  • NextApp Router and Pages Router, with next-i18next v16. Docs
  • AstroMarketing and content sites, plain i18next at build time. Docs

Also React Native and Expo, Node and Deno servers (i18next-http-middleware), and Vue, Angular, Svelte and more by the community.

src/Order.jsx
import { useTranslation } from 'react-i18next'

export function Order({ count }) {
  const { t } = useTranslation('common')
  return <p>{t('loaves', { count })}</p>
}
app/[lng]/page.tsx
import { getT } from '@/i18n.server'  // next-i18next, bound to your config

export default async function Page() {
  const { t } = await getT()
  return <p>{t('loaves', { count: 3 })}</p>
}

How i18next works

Extract
i18next-cli finds texts still written into the code, writes their keys into the files and keeps every language in step with the first. Your agent runs the same commands.
Runtime
In the browser, on the server and at build time, with React, Next, Astro or no framework at all. Plurals, numbers, dates and lists follow the rules of each language (Intl). i18next 27 itself installs no other package.
Structure
One plain JSON file per language and namespace, in your repository. Any editor, any agent and any translation tool can read and change it; your code only knows the key.
